# 任务六：地图搜索、可见物品接近与人物跟随

发布目录、依赖和当前验证状态见[仓库说明](../../README.md)。下方原部署路径为开发记录。


## 可选离线语音（2026-10-30）

保持新的兄弟目录 `../status_voice`，添加 `--voice play` 开启中文播报，
`--voice dry` 仅模拟，默认off。可用 `--audio-device` 选择实际声卡。
到达搜索点、目标停稳完成，以及目标丢失、歧义、视觉/串口/传感器异常等事件会播报。
播报线程不承担运动控制；最终STOP先发送，声音播放失败不会阻止停车。
`--check --voice play`可试听“尚未标定”提示，不打开运动硬件，但会输出音频；
检查输出分别给出hardware_write、motor_write和audio_playback_requested。
完整试听、任务四接入与部署说明见 `../status_voice/README.md`。
自检包含地图模式、可见目标模式和语音集成检查；必须与status_voice一同部署。

## 可见目标模式（2026-10-31）

当前画面已有目标时，使用新增的 `approach` 或 `follow-visible`，不需要把车放回地图起点。
这两个模式不读取地图、不建立世界坐标，也不要求 `start_pose_verified`；车体、地面投影、
识别有效范围和ToF标定仍必须通过。它们没有全局边界约束，不能把“不依赖起点”理解为
任意位置、任意环境下都能安全运行。以下流程面向空旷、有人观察的实车调试。

| 模式 | 行为 | 是否需要地图起始姿态 |
| --- | --- | --- |
| `search` | 按地图搜索，再接近目标 | 是 |
| `follow` | 按地图先找人，再跟随 | 是 |
| `approach` | 接近画面内指定颜色的地面杯子/瓶子，停稳后完成 | 否 |
| `follow-visible` | 跟随画面内指定上衣颜色的人，保持距离 | 否 |

控制过程：静止等待目标 → 连续不同帧确认唯一目标 → 对准并接近/跟随 → 停车或结束。
任务五先确认目标，新控制器再确认3个不同图像帧；重复帧不能累加确认次数。
默认最大前进速度0.05 m/s、转向速度0.3 rad/s。默认等目标10秒，任务最长600秒。
未发现目标时不会原地旋转搜索，也不会沿地图走动。

- `approach`：默认停车距离0.50 m，容差±0.08 m；方向对准、轮速反馈进入静止阈值，
  且新图像持续确认至少0.5秒后，发送STOP并完成；语音开启时再播报完成。
- `follow-visible`：默认距离0.80 m。人往前走就跟进，停下后保持距离；人靠得过近时
  停车，不倒退或继续贴身转向。同一个已锁定目标重新走远后可以继续跟随。
- 目标丢失/编号改变、多个同色目标、图像过期/重启、串口过期、近障或测距不可信，
  结束本次任务并停车；不自动改跟别人，不自动重新锁定。需要重新执行命令才能开始新任务。
- 人物按上衣颜色与短时轨迹区分，不是人脸或身份识别；遮挡、交叉后无法保证仍是同一个人。
- 物品必须落地、人的脚部必须可见且位于标定区域。手持杯子、桌面物品、脚被裁掉的画面
  不适用于这套地面测距。相机安装角度或高度变化后应重新标定。
- 前向ToF和可投影的其他杯子/瓶子/人物用于近障停车，不执行绕障规划；无法可靠投影的
  相关非目标物体也会阻止继续移动。镜头外、侧后方和未识别障碍仍是覆盖盲区。

只检查参数（不打开相机、串口或电机）：

```sh
sh run.sh --check --mode approach --label cup --color red
sh run.sh --check --mode follow-visible --label person --color blue
```

输出应有 `global_start_required: false`。包内标定保持未验证，因而
`calibration_ready: false` 是预期结果，不能直接把验证标志改为true来跳过实测。
确认串口、FPGA兼容固件和实际标定后，才使用执行命令：

```sh
# 选择红色地面杯子，接近至驱动轴中点距目标约0.5米
sh run.sh --execute --mode approach --label cup --color red --distance 0.50 --voice play
# 跟随蓝色上衣人物，保持约0.8米
sh run.sh --execute --mode follow-visible --label person --color blue --distance 0.80 --voice play
```

距离以驱动轴中点为基准，不是车头；车身外接圆和ToF安装偏移需要实测。
`--voice play`可省略。人物跟随期间“保持距离”不是任务完成，不播报完成。
Ctrl+C或本机状态页的停止按钮结束跟随。

这两个模式的状态页展示车身相对目标位置（上为前、左为车身左侧），全局姿态和地图为null。
程序仍以无窗口方式启动任务五；页面不显示实时摄像头图像，也不要同时运行另一份任务五抢占UDP。
本次只修改RK3588程序，沿用任务六UART协议，不新增或烧录FPGA固件。

## 交付范围

地图模式沿用当前map.json的6×4m候选边界、无固定障碍、随机物品在地面的设置；任务参数由明确的类别、
颜色、模式和停车距离组成，不调用大模型。规划在 RK3588，电机闭环在 FPGA。
不是 SLAM、人物身份识别、任意物体检测或任意障碍保证可绕行的系统。

已实现生成观察点/观察方向、A* 栅格规划、车身余量、前瞻路径跟踪、连续里程计、
任务五真实 JSON 视觉适配、地面投影、目标对准/接近、人物跟随、串口会话/确认/超时、
本地状态页面和停止请求。程序默认不打开硬件；实际运动必须显式 --execute 且标定验证通过。

## 数据和坐标

位置为驱动轴中点；单位米、弧度，世界 +X 向右、+Y 向上，逆时针正。
以下地图坐标要求只适用于search/follow。初始位置沿用 S=(0.45,3.15)，朝 +X。启动前必须实际摆到所配置的起始姿态；原任务四的局部原点
与这里的世界坐标不混用。每段路线不重新归零；FPGA 复位或里程计跳变时任务停止。
初版编码器加 IMU 只有相对定位，长距离漂移不自动校正。

map.json 使用0.1m栅格，车身围绕驱动轴的保守外接圆半径0.23m（包括候选余量）。
观察位置从场地自动生成，不局限P1～P6。搜索根据未观察区域和距离选点，到点依次转向
8个方向观察；只有新鲜图像且停稳时更新观察记录。观察覆盖是几何估计，不是无漏检保证。
没有目标时报告搜索耗尽、不可达或超时，并保留未观察区域数，不宣称物品不存在。

动态障碍来自有效地面投影和前向ToF近障点，使用保守圆形近似，不代表精确轮廓。
同一次任务保留已观察的障碍，移动人物可能留下保守的旧障碍，导致无路可走。
没有为了继续运动自动删除旧障碍；当前姿态落入障碍余量或观测不足时停车。
单束ToF看不到整个侧后方、低矮障碍和转弯扫掠区，不能据此保证实车无碰撞。

## 地面标定：必须实际测量

不要只把 false 改为 true。calibration.json 需要真实记录：

1. 轮径、轮距、每圈四倍频编码器计数和轮向；修改 config.json 后实测直行/转向。
2. 固定相机姿态，保持1280×720图像；在实际地面摆至少6个分散的标定点，记录像素
   与驱动轴坐标系中的前向x/左向y米数；另测至少4个未参与拟合的验证点。
3. 若存在明显镜头畸变，提供 camera_matrix/distortion_coefficients，并用同样校正后的
   像素拟合。不能混用未校正与已校正坐标。通过 target_range.fit_ground() 输出 H 与
   独立点最大误差。把测得的有效地面多边形写入 valid_ground_polygon_px（原始像素域）。
4. 实测有效识别距离和水平视角，填入 recognition_*，不能沿用候选值就视为已测量。
5. 核对ToF安装位置与方向，测试目标处于画面中央时的测距对应关系。
6. 记录 evidence 中的测量条件、误差、日期，再将对应 verified 标志置真。

拟合示例（在交互Python中使用真实测量数组，不使用本测试里的合成H）：

```python
from target_range import fit_ground
result = fit_ground(fit_pixels, fit_ground_xy, validation_pixels, validation_ground_xy)
print(result)
```

投影使用检测框底边中点作为候选接地点，拒绝裁切、明显遮挡、有效区域外和超范围结果。
底边不一定是真接地点；杯子/人的实际误差必须验证。人物脚不可见、物体被遮挡、模型框偏差
大时不能可靠测距。ToF只作一致性校验，不能证明测到的一定是选中目标。

## 板端运行条件和步骤

先在config.json中填写已确认的serial_device；/dev/ttyUSB0只是候选值，并非已核实接线。
任务五目录由 config.json 中 task5_root 指定，默认相对配置文件的 `../task5_perception`。
部署包同时携带未经修改的任务五源文件，两个目录保持并列即可，无需覆盖之前的任务五目录。
它复用之前板端部署的视觉模块/模型，启动任务六时由本程序拉起任务五无窗口子进程。
启动前必须停止旧 UI/识别服务，释放 UDP 6102 与 `/dev/ttyUSB0`；本程序不自动停止其他服务。
FPGA必须使用通过验证的新任务六固件，旧固件只有STOP接口，无法执行任务六速度帧。
部署、烧录、标定及实车启动需要按当次确认范围操作。

通过上述检查和现场确认后，完整命令如下；未经标定时会在打开串口前拒绝：

```sh
sh run.sh --execute --mode search --label bottle --color red --distance 0.50
sh run.sh --execute --mode search --label cup --color blue --distance 0.50
sh run.sh --execute --mode follow --label person --color blue --distance 0.80
```

person 默认匹配上衣颜色。跟随会先搜索人物，锁定后跟进，不自动倒车。多人符合条件、
目标编号变化、丢失或距离无效时停止或静止等待，不自动选中另一个人。
Ctrl+C停止任务并尝试发送STOP；主机被直接拔电时由FPGA速度期限停车。
进程不后台重复发送旧速度，不自动重新ARM，人工接管后需要明确重新发起新任务。

板端浏览器打开 `http://127.0.0.1:8096` 查看状态和发出停止请求。
页面只监听本机，默认不对热点开放；不是硬件急停。地图模式页面绘制场地、观测障碍、当前路线、
目标及估计位置，并显示状态数据；不包含实时视频。不能将仿真位置传入实际模式。
